# CI/CD Setup for Greensheet

## Overview
Automated Docker image builds, tests, and deployments using GitHub Actions.

## Workflows

### 1. **test.yml** (Lint & Test)
- **Trigger**: Push to main, PR to main
- **Steps**:
  - Lint with oxlint
  - Unit tests with vitest
  - Docker build test (no push)
  - Layer caching via GitHub Actions cache

### 2. **docker-build.yml** (Build & Push)
- **Trigger**: Push to main (on changes to app/), manual workflow dispatch
- **Steps**:
  - Build frontend and backend in parallel
  - Multi-stage build targeting prod
  - Push to GHCR (ghcr.io)
  - Tagging strategy:
    - `latest` (main branch)
    - Git SHA: `main-abc1234`
    - Semantic versioning (optional, on tags)
  - Trivy security scan (CRITICAL/HIGH only)
  - Upload results to GitHub Security tab
  - Layer caching with `type=gha`

### 3. **deploy.yml** (Deployment Notification)
- **Trigger**: Successful docker-build.yml completion
- **Steps**:
  - Log deployment readiness
  - Create GitHub Deployment record (for tracking)
  - Print instructions for manual SSH deploy or CD integration

## Setup Steps

### 1. Create GitHub Token (one-time)
No additional setup needed — workflows use `GITHUB_TOKEN` auto-generated by Actions.

### 2. Docker Hub Alternative (Optional)
To push to Docker Hub instead of GHCR:

Add secrets to GitHub repo (Settings → Secrets):
- `DOCKERHUB_USERNAME` = your Docker Hub username
- `DOCKERHUB_TOKEN` = Docker Hub Personal Access Token

Update `docker-build.yml`:
```yaml
- name: Log in to Docker Hub
  uses: docker/login-action@v3
  with:
    username: ${{ secrets.DOCKERHUB_USERNAME }}
    password: ${{ secrets.DOCKERHUB_TOKEN }}
```

### 3. Enable Artifact Attestation (Optional)
GitHub Actions automatically signs build artifacts (SLSA provenance). Verify with:
```bash
docker pull ghcr.io/marcusdax/greensheet-app:latest
cosign verify-attestation ghcr.io/marcusdax/greensheet-app:latest
```

## Tagging Strategy

| Event | Tag | Example |
|-------|-----|---------|
| Push to main | `latest` + SHA | `latest`, `main-a1b2c3d` |
| Pull Request | `pr-123` | `ghcr.io/user/repo-app:pr-123` |
| Release tag | `v1.0.0` | `v1.0.0`, `1.0`, `1` |

To enable release tagging, tag commits:
```bash
git tag v1.0.0
git push origin v1.0.0
```

## Layer Caching
All workflows use GitHub Actions cache (`type=gha`):
- Builds are 2-5x faster on subsequent runs
- Cache survives for 5 days (GitHub default)
- No external registry needed

## Security
- Trivy scans for CRITICAL/HIGH vulnerabilities
- Results uploaded to GitHub Security tab
- Build artifacts are signed (SLSA)
- Secrets never logged (GitHub Actions built-in)

## Manual Deployment
After a successful build, deploy with:

```bash
# SSH to production server
ssh user@production.example.com

# Navigate to deployment directory
cd /opt/greensheet

# Pull latest images from GHCR
docker compose pull

# Start services
docker compose up -d

# Verify
docker compose ps
docker compose logs -f app proxy
```

## Troubleshooting

### Build fails on test stage
- Check `npm run test:run` locally
- Resolve merge conflicts in source files
- Push fix and re-trigger workflow

### Trivy scan fails
- Review GitHub Security → Code scanning alerts
- Update base images (node:22-alpine, nginx:alpine)
- Or suppress known CVEs in trivy config

### Images don't push to GHCR
- Verify `GITHUB_TOKEN` has `packages: write` permission (default in Actions)
- Check repo is public or Actions have permission for private registries
- Review workflow logs for auth errors

   - `deploy.yml` → `.github/workflows/deploy.yml`

4. Test by making a PR and observing workflow runs
5. After merge, docker-build triggers and pushes to GHCR
6. Integrate deployment hook or use manual SSH deploy
